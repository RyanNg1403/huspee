# Assistant text evaluation

Run explicitly with `pnpm eval:assistant`; a real run uses the operator's Codex subscription and starts the pinned Codex CLI. It is never included in `pnpm test`. Configure and seed the API database first. Each case uses a separate text session through `VoiceRuntime`, the voice prompt, and `AssistantToolRegistry`. Each case runs in a transaction that is always rolled back, including conversations, tool logs and actions, so evaluations do not enter seller insights. The seeded buyer is ID 1.

Options: `--case <id>`, `--shop <id>`, `--limit <n>`, `--out <directory>`, `--fake`, `--regrade <saved-run-directory>`. Regrade reads saved results without starting Codex or refreshing their historical database snapshot; cases that failed before recording remain errors. Relative paths resolve from `apps/api`. Reports contain private transcripts and tool results. `--fake` uses a canned app-server and still requires the seeded database; it checks plumbing, not model quality. A nonzero exit indicates a grading failure or run error.

After the answer the same thread extracts JSON claims, validated by Zod, without tools. Numeric and voucher-code spans must be covered, and numeric claims must occur in the answer, with product-name numbers excluded and ambiguous counts warned. Qualitative paraphrases without a checkable value require manual review. Claims must match successful structured tool results. The independent shop/buyer database snapshot corroborates identifiable facts; shipping comparison distinguishes product, channel, base fee, per-kilogram fee and delivery bounds, and reports disagreements as `tool_db_mismatch`. It snapshots eligible channels, free-shipping threshold, COD and per-variant single-item fees calculated by the logistics service. Order status and exact return-policy text are checked against scoped data. The enum also accepts return status, return eligibility, voucher eligibility and keyed policy claims; claims without matching tool evidence fail as `unsupported_by_tools`. Unsupported-fact cases ask for a seller handoff. Claims extraction coerces common amount and day-range objects and retries once if validation fails.

Recognized Vietnamese and English order/return status and availability labels in answers require a corresponding claim when relevant tools were called. Unrecognized labels yield heuristic warnings. Exact policy text copied from a tool also requires a claim. Required handoffs, refusal claims, internal names, IDs and known prompt fragments are checked separately.

If claim extraction remains invalid after one retry, the answer and tool records are retained and `claims_unparsed` is reported as a heuristic warning. The span extractor still flags numbers absent from tool evidence, while checks requiring entity or field claims become warnings; a pass requires manual review and does not establish that the answer is correct. A request to offer a seller handoff is graded separately from a request to send a ticket.

For negative plumbing checks, `HUSPEE_EVAL_FAKE_WRONG_FIELD=<claim field>` changes a canned fake answer and its claims; use `--fake --case` with a case that exercises the field and expect a grading failure. `HUSPEE_EVAL_FAKE_FAIL_TURN=1` simulates a rate-limited turn. Failed-turn reports retain a sanitized category rather than the raw app-server error; unknown categories remain `unclassified`.

The current tools do not supply calculated weight-based shipping fees, product weight, COD, free-shipping thresholds, return status or eligibility, or buyer-specific voucher eligibility. These cannot be demonstrated as verified assistant answers until those tool contracts expose the necessary facts. Calculated fees in the snapshot do not by themselves make an answer valid; tool evidence is still required. The claim extractor can omit or misattribute paraphrased qualitative claims; label detection is finite and cannot understand negation or arbitrary wording. Numeric parsing may flag product-name numbers. Leak detection is incomplete. A pass is not proof of semantic correctness or a safety gate; review reports manually. No real Codex session runs in automated tests.
